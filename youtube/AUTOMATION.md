# 영상 편집 자동화 방법 정리

1편(`ep01/`)을 만든 흐름에서 이미 자동인 부분과 아직 손으로 한 부분을 나누고, 2편부터 자동화할 수 있는 방법을 정리했다.

## 1편 작업 흐름 (지금 상태)

| 단계 | 1편에서 한 방법 | 자동? |
|---|---|---|
| 대본 | `lines.json` (한 줄 = 자막 한 줄 = 나레이션 파일 하나) | 손 |
| 나레이션 | ElevenLabs 웹에서 줄마다 생성 → 다운로드 → `place_nar.py`/`place_modi.py`가 생성 순서로 이름 붙여 옮김 | 반자동 |
| 컷 편집 | Vrew에서 남길 구간과 자막을 고름 → `final_ep1.py`/`final_modi.py`가 Vrew 타임라인을 읽어 원본에서 다시 렌더링 | 반자동 |
| 화면 가리기·프롬프트 강조 | `build_ep1.py`에서 좌표를 손으로 정해 ffmpeg 필터로 처리 | 반자동 |
| 자막 | 대본 문장을 실제 음성 길이에 맞춰 번인 + SRT (`narrate_ep1.py`) | 자동 |
| 효과음·BGM | 원본 시각 기준 목록을 손으로 적어 배치 (`final_ep1.py`) | 반자동 |
| 파생 영상 | 쇼츠·릴스, 세로 전체, 1.25배속 (`make_shorts*.py`, `make_vertical_full.py`, `speed125.py`) | 자동 (구간은 손으로 고름) |
| 썸네일·커버 | Pillow로 합성 (`make_thumb*.py`, `make_insta_cover.py`) | 자동 (문구·배치는 손) |
| 검증 | ffprobe + 프레임 확인 + PC에서 직접 재생 | 반자동 |

## 2편부터 자동화할 수 있는 방법

효과가 큰 순서다.

### 1. 나레이션: ElevenLabs API로 바로 생성
- 웹에서 다운로드하고 순서를 맞추는 대신 API로 `lines.json`을 줄마다 보내 `{번호}_{문장}.mp3`로 바로 저장한다. 생성 순서가 꼬일 일이 없다.
- `with-timestamps` 엔드포인트는 글자별 시각을 같이 준다. 이걸 쓰면 긴 문장의 자막을 두 줄로 나눌 때도 정확한 시각에 끊을 수 있다.
- 필요한 것: ElevenLabs API 키(환경변수로만, 저장소에 넣지 않음), 보이스 ID(태형, ModiSungSoo). 유료 플랜의 글자 수 한도 안에서 쓴다.

### 2. 컷 편집: 무음 구간 자동 제거 + 편집 목록 파일
- 녹화 원본의 무음·대기 구간은 ffmpeg `silencedetect`나 `auto-editor`로 자동으로 잘라 1차 컷을 만든다. AI 응답을 기다리는 구간은 잘라내지 말고 배속으로 바꾼다.
- Vrew를 계속 쓸 거면 지금처럼 Vrew 타임라인을 읽는 방식을 공통 함수로 빼서 2편에서도 그대로 쓴다.
- Vrew 없이 하려면 `edit.json`(원본 파일, 시작, 끝, 배속, 줄 번호)을 정본으로 두고 렌더링 스크립트 하나가 그 파일만 읽게 한다. 편집 수정 = JSON 몇 줄 수정 → 다시 렌더링.

### 3. 화면 가리기·프롬프트 강조: 녹화 레이아웃 프리셋
- 녹화할 때 창 크기와 배치를 고정하면 Claude 사이드바와 주소창 위치가 매번 같아진다. 그러면 가림 좌표를 프리셋 하나로 재사용할 수 있다.
- 프롬프트 강조(확대 + 노란색)는 "입력창 영역 좌표 + 시각"만 편집 목록에 적으면 스크립트가 crop·scale·drawbox로 그린다.
- 더 자동으로 하려면 프레임에서 OCR로 입력창 글자를 찾아 시각을 잡을 수 있다. 다만 오탐이 있을 수 있어 사람이 한 번 확인해야 한다.

### 4. 효과음·BGM: 대본에 표시를 달아 배치
- `lines.json` 줄에 `"sfx": "whoosh"` 같은 표시를 달면 그 줄의 나레이션 시작 시각에 효과음이 자동으로 들어간다. 원본 시각을 손으로 적지 않아도 된다.
- BGM은 ffmpeg `sidechaincompress`로 나레이션이 나올 때 자동으로 줄인다(덕킹).

### 5. 텍스트 카드·모션 그래픽: 코드로 템플릿화
- 정산 표 카드처럼 반복되는 그래픽은 지금처럼 Pillow 함수로 두거나, 움직임이 필요하면 Remotion(React로 영상 만드는 도구)으로 템플릿을 만든다. 서체는 나눔스퀘어로 고정한다(맑은 고딕 Regular는 작은 크기에서 '같' 받침이 깨진다).

### 6. 에피소드 공통화
- `ff`, `dur`, `t2s`, `wrap`, `fit` 같은 함수가 여러 스크립트에 복사돼 있다. 2편을 시작할 때 `youtube/common.py`로 한 번 모은다.
- 에피소드마다 바뀌는 값(소스 폴더, 결과 폴더 `Desktop\유튜브\...\N. 제목`, 보이스, 쇼츠 구간)은 `epNN/config.json`에 두고 스크립트는 공통으로 쓴다.
- 최종적으로 `python youtube/make_all.py ep02` 한 번으로 본편, SRT, 쇼츠·릴스, 세로 전체, 1.25배속, 썸네일까지 나오게 한다.

### 7. 검증 자동화 (재생 확인은 남김)
- 렌더링이 끝나면 스크립트가 모든 클립의 해상도·pix_fmt·fps가 같은지 ffprobe로 검사한다(1편에서 yuv444p 클립 하나 때문에 재생이 멈춘 적 있음).
- 이어 붙인 지점과 텍스트 카드 시각의 프레임을 한 장짜리 콘택트 시트로 뽑는다.
- 그래도 마지막에는 PC 플레이어로 직접 재생해서 이음새, 카드, 자막을 확인한다. 이 단계는 자동화하지 않는다.

### 8. 업로드 (선택)
- YouTube Data API로 제목, 설명, 썸네일, 자막(SRT)을 올리고 예약 공개까지 할 수 있다. 올리기 전에 매번 사용자 확인을 받는 전제다.

## 하지 않을 것
- 자막을 음성 인식으로 새로 만들지 않는다. 자막은 대본 그대로 쓴다(인식은 시각 맞추기에만 쓸 수 있다).
- Higgsfield 등 크레딧이 드는 생성은 허락 없이 파이프라인에 넣지 않는다.
